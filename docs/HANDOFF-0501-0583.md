## 5. BirdLife DataZone 抓取規則

```
https://datazone.birdlife.org/species/factsheet/<english-name-slug>-<genus>-<species>/details
```

- **BirdLife 的英文名不一定等於 runtime 的 `comName`**，404 時依序試：① 該屬另一常用名（如 0496 = `white-tailed-blue-robin-myiomela-leucura`，**不是** `white-tailed-robin-…`）② 較舊的英文名（0497 = `orange-flanked-bush-robin-tarsiger-cyanurus`）③ `web_search`「datazone.birdlife.org <學名>」找線索。
- 相鄰物種的事實頁有 **Previous / Next** 連結，抓到一張就可以沿著走到同屬其他種（0498 → 0499 → 0500 就是這樣走過去的，0501 琉球姬鶲應該是 `narcissus-flycatcher-ficedula-narcissina` 的 Next）。
- 要抄進 `sources[].use` 的重點：**IUCN 類別與評估年份、成熟個體數、趨勢與推導方式、EOO（繁殖／非繁殖）、遷徙狀態、breeding endemic、IBA/KBA 數、海拔、世代長度、森林依賴度、生態系統、生境分類與重要性、貿易普及度、保護行動、國家表（原生／迷鳥分開）**。

## 6. 規格檔（`scripts/cards/info-restart-<id>.json`）要點

- 直接以 `scripts/cards/info-restart-0500.json` 為模板複製再改。欄位：`layout/size/status/iucn{code,zh,assessmentNote}/id/name/scientificName/illustrationTaxon/similarSpecies[2]/featureCrops[4]/featureLabels[4]/featureNotes[4]/featureSources[4]/rangeMap{…}/sources[]/notes[]/missingScores/withheldScores`。
- `iucn.assessmentNote` **不得超過 26 個字元**，格式如 `全球 LC：BirdLife 2025 評定`。
- `similarSpecies[].framing` 一律 `"whole-bird"`；`distinction` 用繁體中文、可用 `**粗體**`。
- `featureSources` 通常是四個 `"pixel.png"`。
- `notes` 至少要有：香港狀況、辨識要點、IUCN、地圖說明、runtime 資料缺陷（只記錄、不改 runtime）、AI 主圖與比較鳥的來源聲明（**非等比例、非專家認證**）。

### 分數處理（`missingScores` vs `withheldScores`）

- **runtime 整個缺某軸** → 放 `missingScores`。例：0499 缺 `a` → `["a"]`。
- **runtime 有值但無從核對** → 放 `withheldScores`（**每項都要寫理由字串**），卡面顯示「待查」。
  - 0494：`a` 只有一句分類描述 → withheld `a`，並因 `o` 依賴 `a` 而一併 withheld `o`（另有 `i`、`c` 缺分）。
  - 0496：`look` 只有別名 → withheld `a` + `o`，卡面「綜合評分待查」。
  - 0490：`look` 只有俗名列表 → **保留 `a`**，只在 notes 記「無文字可核對」。**這是舊先例，新卡請採 0494／0496 的從嚴做法。**
- 六軸齊全且 `look` 有形態描述 → 兩個欄位都是空的（0495、0497、0498、0500）。
- 卡面綜合分 = runtime `o`；`o` 空才顯示「綜合評分待查」。

## 7. 圖片規則（重要教訓）

- 目標畫風：**暖橄欖卡其紙底、細墨線＋淡彩水彩的博物圖鑑插圖**，整隻鳥完整入鏡、四邊留邊。
- 尺寸：主圖 `pixel.png` **1127×1127**、比較鳥 `sim*-square.png` **816×816**。**不要補邊、不要拉伸**；模型常常回 1024² 或 1408×768，**正方形就直接放大、橫幅就取中央正方形裁切**（用 PIL `crop` 再 `resize`，`Image.LANCZOS`）。
- **帶參照圖會被照抄**：0497 的主圖當參照時，0498 的主圖變成一隻藍色橙脅的小鳥。**0498、0499、0500 改成完全不帶參照、把羽色寫成硬性規格（例如「頭、背與尾是純黑，不是藍色；任何地方都不得出現藍、橙或紅褐」）**，命中率高得多。建議沿用此做法；若一定要參照，選同色系、不會誤導的圖。
- 比較鳥優先**沿用已生成的方形圖**（例如 0501 可用 0498 白眉姬鶲、0499 綠背姬鶲、0500 黃眉姬鶲），這樣三張卡可以互為比較鳥、風格一致又省一次生成。
- `crop-preview.py crops` **必須逐格目視**：常見問題是圓圈落到背景、兩格拍到同一片羽毛、或整格只剩羽毛紋理。**每張卡平均要調一次以上**；「背／通體」這類特徵最容易失敗，可改找**同一個體上另一個可指認的部位**（0495 第 4 格由「褐背」改成「淡粉長腳」、0500 第 4 格由「黑頭頂」改成「白色下腹」）。

## 9. 地圖規則

- 只填 BirdLife **原生（Native）**且 **Natural Earth 110m 有幾何**的國家／地區（ISO3）。
- **沒有 110m 幾何**：`HKG`、`MAC`、`SGP`、`AND`、`FRO`、`LIE`、`MLT`、`PLW`。
  - BirdLife 若把 **Hong Kong** 列為原生 → **要在地圖 `note` 明確寫「香港原生但無 110m 幾何，以文字說明而不填色」**（0494、0495、0497、0500 都是這樣）。
  - BirdLife 若**未列香港** → 不要提香港（0496、0498、0499）。
- **迷鳥（Vagrant）一律不填**，可在 note 列出被排除的國家；`Origin Uncertain`（如 0497 的阿富汗）亦不填。
- 俄羅斯的多列（Russia / Russia (Asian) / Russia (Central Asian) / Russia (European)）只算**一個** `RUS`。
- `note` 開頭固定寫 `Partial NATIVE-country overview only.`，結尾要有「非 occurrence polygon」的說明並附 EOO 數字。
