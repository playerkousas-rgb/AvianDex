# 資訊圖卡版式規格（滿版資料卡 / dexcard）

> **唯一視覺基準**：`NO.0008 鵲鴝` 成品卡（用戶 2026-11-04 提供）。
> 樣張（由本 repo 引擎重繪）：[docs/assets/dexcard-0008-example.png](./assets/dexcard-0008-example.png)
>
> 任何人改版面之前：先開樣張對一次。**未經用戶同意，不可自行發明新欄位或新造型。**
> 舊的「寶可夢圖鑑機（紅機身大鏡頭）」與「2×2 格仔」版式**已作廢**，
> 程式碼仍留在 `render-card.py`（`--layout pokedex` / `--layout grid`）只為對照，勿用作出圖。

- 引擎：`scripts/cards/render-card.py` → `render_dexcard()`
- 尺寸：**1200×1600**（3:4），輸出 AVIF 至 `cards/out/info/NNNN.avif`（R2：`aviandex/info/NNNN.avif`）
- 文字：**100% 由 Noto Sans TC 字型渲染**，AI 只負責像素插圖、真雀相、欄底小插圖
- 資料：`src/data/{birds,birdTaxonomy,cardCopy}.json`，缺欄一律印「資料待查」

## 2. 每格要吃哪個欄位

| 卡面位置 | `cardCopy.json` 欄位 | 上限 | 來源性質 |
|---|---|---|---|
| ① 中文名／學名／英文名／目／科 | `birds.json`、`birdTaxonomy.json` | — | eBird/Clements（權威） |
| ① 身長 | `length` | 14 字 | 維基原文 |
| ① 體重 | `weight` | 18 字 | 維基原文 |
| ① 常見度 5 燈 | `rarity`（0–5 整數，0＝待查） | — | **編者主觀** |
| ② 像素圖 | `sprite`（`cards/art/`） | — | AI 像素插圖 |
| ② IUCN 徽章 | `iucn` | 12 字 | 維基／IUCN |
| ② 別名 | `aliases`（陣列） | 每項短詞 | 維基原文 |
| ② 真雀相 | `photo`（`cards/art/`） | — | 需授權來源 |
| ② 圓形特寫 | `callouts[]`：`label`／`text`／`fx`／`fy`／`zoom` | 5 個 | 維基原文（外形） |
| ② 名稱由來 | `etymology` | 短段 | 維基原文 |
| ③ 基本介紹 | `intro_zh` | 140 字 | 維基原文 |
| ③ 分類資訊 | 自動組合 ＋ `iucn`、`code` | — | eBird ＋ IUCN |
| ④ 分佈地區 | `range` | 46 字 | 維基原文 |
| ④ 棲息環境 | `habitat` | 46 字 | 維基原文 |
| ④ 食物 | `diet` | 46 字 | 維基原文 |
| ④ Top 5 特色亮點 | `highlights[]`（**剛好 5 條**） | 每條 ≤ 40 字 | **編者撮寫**（每條都要對得上來源句） |
| ⑤ 成長與繁殖 | `breeding` | 160 字 | 維基原文 |
| ⑤ 觀察小貼士 | `tips[]`（最多 4 條） | 每條 ≤ 40 字 | **編者經驗** |
| ⑤ 有趣冷知識 | `funFact` | 60 字 | 維基原文 |
| ⑤ 注意事項 | `caution[]`（最多 3 條） | 每條 ≤ 40 字 | **編者建議** |
| ⑥ 五項評分 | `scores{}`（5 項，0.5 級）＋ `score_notes{}` | 每項解釋 ≤ 16 字 | **編者主觀** |
| ⑥ 綜合評分 | 由 `scores` 平均自動計 | — | 計算值 |
| ⑦ 來源聲明 | `facts_note` | 一行細字 | 必填 |
| ⑦ 版本 | `VERSION` 常數 | — | — |

**固定 5 項評分名稱**（測試會驗，不可改名）：
`生態重要性`、`適應力`、`觀賞價值`、`研究價值`、`保育關注度`。

## 3. 三類資料不可混淆

| 類別 | 例子 | 卡上如何處理 |
|---|---|---|
| 權威分類 | 目／科／學名／species code | 直接印，附 eBird |
| 可追溯原文 | 身長、體重、分佈、棲地、食性、繁殖、冷知識、名稱由來 | 印原文／貼近原文，`source` 記 pageid |
| **編者主觀** | 常見度、Top5、觀察小貼士、注意事項、生態價值 5 項、綜合評分 | 必須有 `facts_note` 聲明「編者依觀察經驗主觀評分，非科學數據」 |

> 用戶表明「我沒有核對資料的能力」，所以**每一格都要自帶來源**；
> 主觀欄位要明講是主觀，唔可以借維基的口吻講。

## 4. 排版引擎的硬性規則

1. **文字先量度、後排版**：`need()` 逐格計算行數，動態調整字級（15pt → 11pt）與行高；
   內容放唔落時縮字，**不截斷、不省略號**（截斷＝漏字＝講一半）。
2. **字型缺字檢查**：圖示只用 Noto Sans TC 一定有的中文字（分／居／食／五／育／貼／知／注／名／形）。
   用 ⌂ ☘ ☺ ⚠ 這類符號會變成方框 —— 已踩過。
3. **冇資料就明講**：像素圖缺 → 「未提供像素圖」；相缺 → 「（未提供真雀相）」並改印外形段落；
   常見度 0 → 「資料待查」；冇 `scores` → 綜合評分印「資料待查」。
4. **冇相就唔畫圓圈**：`callouts` 只會在 `photo` 存在時才畫（測試會擋）。
5. **英文藥丸自適應**：`Black-backed Dwarf-Kingfisher` 這類長名會自動縮字，不壓到右邊目／科。

## 5. 出圖指令

```bash
python3 scripts/cards/render-card.py 0008              # 出 PNG + AVIF
python3 scripts/cards/render-card.py 0008 --preview    # 只出 PNG（改版面時用）
npm run cards:render -- 0008                           # 同一支引擎（Node 包裝）
```

改完版面請跑：`npm test`（48 項，含 dexcard 欄位契約）＋ `npm run lint`。

## 5.5 「有就講，冇就講其他」的降級規則

用戶原話：「資訊卡內有些資料未必是所有雀都有，總的來說就是有就說，沒有其他特點也可以說」。
所以引擎**不可因為缺一欄就整張卡變空**，要逐格降級：

| 缺什麼 | 卡面如何降級 | 程式位置 |
|---|---|---|
| 真雀相 | 右邊由 5 個圓圈改成「外形特徵」文字格；中央印「（未提供真雀相）」 | `render_dexcard()` 的 `has_photo` |
| 像素圖 | 畫虛線佔位框 + 「未提供像素圖」 | `sp` 為 `None` 時 |
| `callouts` 少於 5 條 | 按實際條數平均分佈，不補空圈 | `gap = (calls_h - 20S) / n` |
| `highlights` 少於 5 條 | 印實際條數；列表欄上限 5 | `box()` 的 `items` |
| `scores` 缺 | 綜合評分印「資料待查」，不印 0 分 | `if scores:` |
| `rarity` = 0 | 常見度印「資料待查」，不點燈 | `if rarity:` |
| 其他文字欄缺 | 該格印「資料待查」，其餘照印 | `para()` 前的 `payload or PENDING` |

> 因此 **21 張先做完全可行**：資料齊的出滿版，未齊的同版式降級出卡，
> 日後補到資料重跑即自動升級，不需要另開一套版式。

## 7. 兩個實作（同一個版式，兩個引擎）

同一套版面有兩個實作，**輸出一致，任你揀**：

| | A · Pillow 引擎 | B · 卡面工作室（HTML） |
|---|---|---|
| 檔案 | `scripts/cards/render-card.py` | `tools/card-studio/aviandex-studio.html` |
| 適合 | 批次出 559 張、CI、AVIF | 人手逐張檢視、即時改字、給非工程師用 |
| 文字 | Pillow + Noto Sans TC | HTML + CSS（瀏覽器字型） |
| 改字 | 改 JSON | 卡面內「編輯這一張」即時改 |
| 輸出 | AVIF 159 KB | PNG（SVG foreignObject）／列印 PDF |
| 資料檢查 | `npm test`（48 項） | `build-studio-data.mjs` 版面預算報告 |

> 工作室的靈感來自用戶提供的兩份 HTML，各取一半：
> `漫畫.html`＝**出圖機**（Gemini 出圖、模型降級、錯誤診斷）→ 借它的出圖流程；
> `ai_scout_app (1).html`＝**只准用 git 內檔案回答的 LLM 對答機** → 借它「答案只可來自檔案」的原則，
> 所以卡面文字全部由 `src/data/*.json` 注入，AI 一個字都唔准寫。
> 用法與設計說明：[tools/card-studio/README.md](../tools/card-studio/README.md)

```bash
node scripts/cards/build-studio-data.mjs     # 重新產生單檔工作室（內嵌最新文案）
```
