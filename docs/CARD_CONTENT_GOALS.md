# 資訊圖卡要放什麼（內容目標）

> 一句話：**深度百科已經在 App 裡面（康奈爾 All About Birds / eBird / Xeno-canto / Flickr / YouTube / Merlin）。
> 圖卡不是百科，圖卡是「吸引你按落去」的那一頁。**

這份文件的用途：日後任何人想加一個欄位，先問「這一格會不會令小朋友想收藏／想睇落去」。
唔會，就唔好加——就算資料好齊。

---

## 1. 圖卡在整個 App 的角色

```
圖鑑格子（NO. NNNN）
   │  未發現 = 剪影，發現 = 卡面
   ▼
圖卡（一圖看清）           ← 你現在看的這張：只負責「吸引」
   │  按一下
   ▼
六宮格科研終端            ← 真正深度的內容全部在這裡
   深度百科 · 觀察雷達 · 視覺圖庫 · 影片中心 · 鳴聲資料 · AI 辨識
```

所以圖卡**不需要**替代百科：不需要完整分佈圖、不需要亞種清單、不需要長段落。
它只需要令小朋友「哦！我想見真嘅」。

## 2. 卡面要回答的三個問題（順序就是版面順序）

| 順序 | 小朋友心裡的問題 | 卡面用什麼答 |
|---|---|---|
| 1 | **「呢隻係咩？」** | 大中文名 + 英文名 + 學名 + 目／科標籤（一眼分類） |
| 2 | **「佢有咩特別？」** | 插畫 + **2–3 個特徵標註**（唔係一整段外形描述） |
| 3 | **「我可唔可以見到佢？」** | 稀有度／在香港邊度幾時見到（收藏感的核心） |

「食性／分佈／外形／棲地」四格是**大人的資訊架構**，對小朋友只是「一堆字」。
保留與否見第 4 節的待你決定項目。

## 3. 收集感（Collect）要怎麼體現在卡上

現時卡面已經有的收集元素：

- `NO. NNNN` 編號（＝ R2 檔名，永不變）
- 「資料完整度 DATA x/6」進度條
- 未發現槽位顯示剪影（UNDISCOVERED）

現時**未有**、但屬收集感核心的（需要你拍板）：

| 元素 | 為什麼有效 | 資料可否自動得出 |
|---|---|---|
| **稀有度**（★1–5） | 寶可夢最核心的「值唔值得追」 | 可以用 eBird 在香港的記錄頻度分級，但**需要 eBird API key**；或先用人手分級 |
| **屬性／分類徽章**（水邊、森林、城市、猛禽…） | 一眼知「呢隻住邊」 | 可由 eBird 科＋棲地關鍵詞推，但要小心不可亂作 |
| **香港邊度見到** | 直接驅動「出去找」 | HKBWS 名錄／eBird 熱點資料 |
| **幾時見到（留鳥／冬候鳥／過境）** | 季節任務感 | 可由 eBird 狀態或 HKBWS 名錄得出 |
| **叫聲 QR** | 掃一下就聽到，小孩最受落 | 用 Xeno-canto 該物種頁；QR 只放「已核對的網址」 |
| **「已捕捉」印章** | 自己影到／錄到才算 | 需要 App 內記錄（BirdEx 捕捉流程） |

## 4. 現在卡面被質疑的地方（我的檢討）

1. **四格文字太多**：`食性／分佈／外形／棲地` 每格 20–40 字，小一字都唔會讀。
   → 建議：改成 2 個「哇」位（例如「會懸停定住喺空中」「全港最常見嘅翠鳥」），
   其餘收去 App 內頁。
2. **資料來源／pageid 印在卡面**：對「吸引」冇幫助（但係你要求可追溯，所以搬去卡背／內頁更好）。
3. **「資料完整度 x/6」**：對收藏家有進度感，但對小朋友難理解 → 可改成星等或收集印章。
4. **AI 插畫 vs 真雀照片**：吸引小朋友，插畫（圖鑑風）較統一；但如果要「我真係見過」的說服力，真照片更強。

以上四點等你決定，我才改版面——**唔會再自行加欄位**。

## 5. 圖片生成方式（保持開放）

三條路都可以並存，因為最終都係出同一尺寸 AVIF：

| 方式 | 好處 | 風險 |
|---|---|---|
| **A. 腳本排版**（現時 `render-card.py`） | 文字 100% 準、可批次 559 張、可改一行全改 | 版面偏「工整」，缺少手繪感 |
| **B. AI 一次生成整張卡**（例如 Gemini） | 觀感最吸引、最有「卡」味 | 文字會錯字／亂碼；每張要人手檢查；不可批次無人看管 |
| **C. 混合**：AI 出底圖（無字）＋ 腳本疊字 | 兼得觀感與準確 | 需要 AI 圖留白位對得上版面 |

我的建議：**主力 B 做「封面級」的少量卡（例如香港 30 種常見鳥），A 做其餘 559 張的底卡，C 用於日後改版。**
B 產生的圖，文字錯誤要逐張人手核——所以只做少量。

## 6. 與 BirdEx 的關係

- **AvianDex**（本 repo）：圖鑑＋知識＋「看得到、學得到」。
- **BirdEx**（同一 GitHub 帳戶的另一個 repo）：觀鳥／影相**捕捉 → 儲卡**的流程。
- 兩者共用：`NO. NNNN` 編號、AVIF 卡面規格、eBird 分類權威。
- 分工原則：AvianDex 產生「卡」與「知識」，BirdEx 產生「我捕捉到嘅記錄」。

## 7. 批量補資料的現實做法（2026-11-04 更新）

「先把資料補齊」現在有一條**可以無人看管跑完 559 張**的路：GitHub Actions。

原因：開發沙盒禁止連 `zh.wikipedia.org`（`SSL_ERROR_SYSCALL`），但 GitHub Actions runner 可以。
所以抽取器（`scripts/cards/extract-copy.mjs`）留在 repo，用 workflow 跑：

```bash
# 本機（有網即可）
node scripts/cards/extract-copy.mjs --all --missing-only --delay 600
```

輸出直接寫 `src/data/cardCopy.json`，每張卡自動附 pageid。跑完之後只需：

1. `npm run test:copy`（檢查長度／簡體字／有無 source）
2. 看 `reports/copy-extract.md` 的「仍缺」欄，就知道哪幾張是「維基條目本身冇料」
3. 那些才需要人手換來源（HKBWS 名錄／香港鳥類圖鑑）

> 注意：AI 不會參與寫字。抽唔到就是抽唔到，卡面會印「資料待查」。
