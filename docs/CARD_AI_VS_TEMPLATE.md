# 一次生成（Gemini / Nano Banana）實測與判定

> 實測日期：2026-11-04 · 由 Arena agent 在沙盒直接跑同一版式兩次
> **目的**：答兩個問題 ——（1）中文字會唔會爛？全部改英文會否成功？
> （2）可唔可以做成 Canvas／空白模板，每次只填編號＋鳥名？

## 0. 結論（先講答案）

| 問題 | 答案 |
|---|---|
| 中文字會唔會爛？ | **會，而且是「肉眼看起來漂亮但內容是假的」那種爛** —— 最危險 |
| 全部改英文就會成功？ | **唔會**。英文一樣會亂寫，只是「亂得像英文」所以更難察覺 |
| 可否做成 Canvas／模板，只填編號＋鳥名？ | **可以，但只能做「冇字或少字」的層**；字一定要機渲染 |
| 559 張可否全自動無人看管？ | **一次生成唔可以**；排版引擎可以 |

## 1. 實驗設置

同一句 prompt 結構、同一個模型、同一日：

| 組別 | 內容 | 檔 |
|---|---|---|
| 中文組 | 卡面全部繁體中文，四欄各 30–40 字，底部 5 項評分 | `cards/art/test-fullcard-zh.png` |
| 英文組 | 同樣版面、同樣資訊量，全部改英文 | `cards/art/test-fullcard-en.png` |

兩組都要求：3:4、深綠外框白卡身、NO.0008 膠囊、鵲鴝、`Copsychus saularis`、
中央真雀相 + 5 個圓形特寫、四欄標題＋內文、底部 5 項評分 + 綜合 4.3/5。

## 2. 中文組實測結果

**成績：版面 A、文字 C。**

| 項目 | 結果 |
|---|---|
| 標題 `NO.0008` / `鵲鴝` / `Copsychus saularis` / `Oriental Magpie-Robin` | ✅ 全對 |
| 9 個欄目標題（分佈地區／棲息環境／食物／Top 5 特色亮點／成長與繁殖／觀察小貼士／有趣冷知識／注意事項） | ✅ 全對（罕見地好） |
| 內文 | ⚠️ 9 成字形正確，但**內容是編出來的** |
| 評分文字 | ✅ 五項名稱與分數都印對，但 ⚠️ 星數與分數**唔對應**（3 分畫了 3.5 星） |

內文實際抓到兩個問題（原文照錄）：

1. **重複詞**：「主要…包括甲蟲、蜈蚣、**毛蟲、蜈蚣**等。也會吃**小型的小型的**無脊椎動物」
2. **假事實**：寫「食物：…果實和種子」「香港是常見鳥類」「喜在地面覓食」
   —— 這幾句**不在**中文維基頁（pageid 219197）裡，是模型自己補的。

> 判斷：**中文字本身這次意外地準**（比預期好，Nano Banana 對漢字筆畫有進步），
> 但「字對 ≠ 資料對」。要逐句核對 260 字，559 張＝145,000 字，人手核不可能。

## 3. 英文組實測結果

**成績：版面 A−、文字 D。**

標題與欄目名全對（`RANGE` / `HABITAT` / `DIET` / `TOP 5 FEATURES` /
`BREEDING` / `WATCHING TIPS` / `FUN FACTS` / `CAUTION` / `ECOLOGY 4.5` …），
但內文出現**通順的假英文**，比中文更難察覺：

| 卡面實際文字 | 問題 |
|---|---|
| `Range is Cumor in Danwanca in eostern sround and anses around its North eastern, norgrounded of North & Oriental Magpie-Robin.` | 幾乎全句都是假字（Cumor / Danwanca / eostern / sround / anses / norgrounded） |
| `Habitat hights with tlactural plaved provided mslximal and barces overly water ramoses...` | 同上，字字像英文但無意義 |
| `Oriental Magpie-Robin are se monish most people chindentrals in iacuow, this instects malbors md thip more of...` | 同上 |
| `The species is also known to be a bird of the forest edges and second growth.` | ← 這種「完全正確」的句子才是最大陷阱：讀者會以為其他句都對 |

**為什麼英文「看起來成功」？**
1. 圖片細、字細，讀者（尤其小朋友）只掃視，唔會逐字讀；
2. 假字符合英文拼寫統計，大腦會自動校正成有意義的字；
3. 中文假字（方框、錯字）一眼看出，英文假字看不出 → **風險更高，不是更低**。

## 4. 關於「全英文」的實際結論

- 若目的只是**裝飾性英文標題**（`RANGE`／`DIET`）→ 一次生成可靠，可用。
- 若內容是**要人閱讀的句子** → 全英文**沒有解決問題**，只是把「錯字」換成「假字」。
- 若真的想避開中文字型問題 → 應該走「英文字由 AI 畫、中文名由程式印」的混合，
  而不是「全部交給 AI 寫英文」。

## 5. Canvas／模板路線：可行，但要分層

你的想法是對的，而且可以做得比「每次貼一大段 prompt」好很多。關鍵是**把卡分成兩層**：

```
第一層（AI 生成一次，可重複用）     第二層（程式每次填）
┌──────────────────────────┐      ┌────────────────────────┐
│ 背景、外框、綠框、欄位底   │  +   │ 所有文字               │
│ 像素圖位、真雀相位        │      │ 中文名／學名／數據      │
│ 插圖（地圖、巢蛋、音符）   │      │ 四欄內文、評分、條碼    │
│ ⚠️ 完全不含任何文字        │      │ （Noto Sans TC 渲染）   │
└──────────────────────────┘      └────────────────────────┘
```

**只填編號＋鳥名** 之所以行不通：卡上 80% 面積是文字，冇文字嘅模板就等於冇卡。

**可行做法（我建議的「Canvas 式」）**：

| 做法 | 你要做的 | 結果 |
|---|---|---|
| **C1 · 固定模板 + 資料表**（推薦） | 在 `src/data/cardCopy.json` 改／加一行，跑一支指令 | 100% 一致、文字必然正確、559 張可無人看管跑完 |
| **C2 · AI 底圖 + 程式疊字** | 先叫 AI 出一張「無字版」卡底（一次），之後所有卡都用同一張底 | 有 AI 質感，但每張卡長得一樣 |
| **C3 · AI 出整張（每次貼 prompt）** | 每次貼長 prompt，再逐張人手核字 | 最靚，但 559 張 × 核 260 字＝不可行 |

你說「只需每次打上編號和鳥名」→ 那其實就是 **C1**，而你想要的「不用貼 prompt」
已經存在：`npm run cards:prompt -- 0008` 會自動由 JSON 砌 prompt；
更好的做法是**連 prompt 都不用**，直接跑排版引擎：

```bash
python3 scripts/cards/render-card.py 0008 --preview   # 只出 PNG 睇版
python3 scripts/cards/render-card.py 0008             # 出 PNG + AVIF
python3 scripts/cards/render-card.py --all            # 全部有資料的卡
```

要「打編號＋鳥名」就出卡 → 就是這三行。沒有 AI 參與文字，所以永遠不會有假字。

## 6. 建議的實際分工（回應你「有就講，冇就講其他特點」）

你說得對：**唔係每隻雀都有齊資料**。所以新版 `render_dexcard()` 已經係「有就印、冇就換講法」：

| 情況 | 卡面會怎樣 |
|---|---|
| 有真雀相 | 中央大相 + 5 個圓形特寫 |
| 冇真雀相 | 右邊改成「外形特徵」文字格，唔會留空圈（測試會擋） |
| 有 5 條 Top5 | 編號清單 |
| 少過 5 條 | 印實際條數，不強湊 |
| 冇 `scores` | 綜合評分印「資料待查」，不印 0 分 |
| 欄位缺 | 該格印「資料待查」，其餘格照印 |

所以「21 張先做」完全不是問題：**資料齊的先出滿版卡，未齊的先出簡版**，
同一支引擎、同一個版式，日後補到資料就重跑，卡會自動變豐富。

## 7. 一句總結

> **AI 可以決定「好不好看」，但不可以決定「寫甚麼字」。**
> 想批量、想準、想小朋友學到正確的東西 → 文字必須由資料 + 程式渲染；
> AI 留在「畫」的崗位（像素圖、真雀相風格、插圖、無字底圖）。
